# 一次性批准状态管理：未安装的原型

这一阶段新增 `scripts/deploy/migration_approval_ledger.py` 和临时目录测试，
**没有生产命令入口、安装脚本、sudoers 模板、固定生产路径或生产工作流接入**。
它不连接 GitHub/SSH/数据库，不执行 SQL、不控制服务，也不建立生产批准或账号。
不要把这个模块或此前的离线校验器直接加进 sudoers。

## 一次性指的是什么

批准编号只能从 `approved` 领取一次，领取后成为 `claimed`。
之后只能记录 `succeeded`、`failed` 或 `interrupted`，不能恢复到 `approved`。
同一个编号不能重新注册，哪怕内容完全相同或上一次成功。
注册新的编号也不能绕过已有未解决的失败/中断。

这里保证的是在完整、未被管理员回退的账本中，一次批准最多领取一次。
**它不保证 SQL 恰好执行一次，也不证明调用者记录的成功意味着数据库真的成功。**
部署账号、GitHub runner 和批准 JSON 都不是管理员身份凭据。
未来必须由管理员控制的固定入口保管账本，且不得把注册/初始化/完成接口直接开放给部署账号。
root 可以修改文件或恢复旧账本；普通哈希不能对抗恶意 root 或管理员回退账本，恢复时必须核对数据库和审计记录。

## 内容绑定与重新检查

- 管理员注册接口复用离线校验器，检查批准与已经验证的 CI 包、历史、有效期和备份声明。
- 保存完整批准记录及其规范化 JSON 的 SHA-256，空白或字段顺序不同不会改变内容哈希。
- 领取只接受批准编号，从账本读取原批准，不能由调用者替换批准 JSON。
- 领取时重新校验提交、run/attempt、SQL/ZIP 哈希、迁移范围、历史和有效期。
- 领取生成独立随机 attempt ID，完成记录必须匹配该 ID 及批准内容哈希。
- 返回的领取结果始终包含 `execution_authorized: false` 和 `sql_executed: false`。

这些仍然只是在比较传入的已验证包信息和历史快照。
未来执行器必须自己在线验证产物、取得数据库锁并查询实时历史/目标结构、核查独立备份证据；
不能把不可信的调用者输入当成这些事实的证明。读取账本时重建的上下文仅用于结构一致性检查，不是来源认证。

## 持久化设计

Linux 后端要求预先存在的 root 所有真实目录，权限 `0700`，所有父目录也必须可信且不能被组/其他用户写入。
这个模块不会创建目录、修改所有者/权限，也没有降低检查要求的生产参数。

目录中仅使用固定名称 `ledger.lock` 和 `ledger.json`，均要求 root 所有、`0600`、普通文件、单硬链接。
打开文件使用不跟随链接和非阻塞标志，拒绝符号链接、FIFO、公开权限、错误所有者及锁文件替换。
明确初始化使用独占创建；已有任一文件时拒绝初始化，不覆盖或自动修复。
正常操作发现锁文件/账本缺失、损坏或字段不一致时立即停止，不会当成空账本。

全部读取、检查、转换、保存过程在同一文件锁内完成。
采用单个账本文件，避免“单条记录已更新、全局 pending 尚未更新”的多文件不一致窗口。
保存顺序是写私有临时文件、刷新文件、原子替换账本、刷新目录；这些步骤完成后才返回领取结果。
该文件锁只协调本模块，**不会锁住数据库或现有应用部署工具**。

保存失败时不返回领取结果：

- 替换前失败：旧状态仍在；没有返回可进入后续阶段的领取结果。
- 替换后目录刷新失败：状态可能已经变成 `claimed`；保留现状，不能擅自删除记录并重试。
- 领取完成后进程退出：`claimed` 状态留在磁盘，新的领取被拒绝。

`claimed`、`failed` 和 `interrupted` 都阻止其他批准领取，必须先由管理员检查。
已成功的批准保留用于防重放，允许其他有效批准领取；后续真实历史变化仍应使旧迁移范围的批准失效。
最多保存 64 条记录、账本最多 16 MiB；满了会拒绝注册，不自动删记录、清理、重置或回收编号。
本阶段**没有恢复/解除阻塞接口**；管理员恢复流程需要下一阶段单独设计。

实现参考：[Python 文件锁](https://docs.python.org/3/library/fcntl.html#fcntl.flock)、
[文件同步](https://docs.python.org/3/library/os.html#os.fsync)及
[原子替换接口](https://docs.python.org/3/library/os.html#os.replace)。
原子替换、文件锁和同步调用并不代表对所有存储硬件/灾难场景的绝对保证，仍需保留恢复记录和外部备份。

## 仅在临时目录验证

本地 Windows：

```powershell
python -m unittest discover -s scripts/deploy/tests -p test_migration_approval_ledger.py -v
python -m unittest discover -s scripts/deploy/tests -v
```

便携测试验证状态转换、重复领取、内容变化、过期、错误历史、未知编号、错误完成结果、
未处理任务阻塞、损坏记录和容量限制。

Linux 测试在测试 runner 的临时目录中运行，不需要 sudo、不使用 `/etc` 或任何生产路径。
仅在测试中适配临时目录的所有权/父目录与有效 UID；真实 Linux 文件权限、dir_fd、
`O_NOFOLLOW`、`flock`、`fsync`、原子替换和独立进程竞争仍使用实际系统调用。
测试包括两个进程竞争只允许一个领取、领取后直接退出仍阻止重试、文件/目录刷新失败及记录保留。
进程退出测试不是实际断电或磁盘故障测试，不能据此宣称完整的生产灾难恢复验证。

Windows 明确跳过真实 Linux 后端测试；CI 现有 unittest discovery 会在 Ubuntu runner 中运行这些用例。
后续新增了[执行流程 CI 验证](MIGRATION_EXECUTION.md)，在临时库中连接真实 SQL 会话与本账本。
CI 增加专门的测试步骤；生产 CD、一次性批准机制和现有 Ubuntu 授权仍未启用或修改。
